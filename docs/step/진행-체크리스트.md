# Daily Study 진행 체크리스트

> 프로젝트 전체 진행 상황을 한 곳에서 확인하고, 작업이 완료될 때마다 체크합니다.
> 단계는 위에서 아래 순서로 진행합니다. 앞 단계의 결정이 바뀌면 영향을 받는 뒤 단계 항목을 다시 확인합니다.

## 문서 작성 및 폴더 규칙

- 체크리스트의 대분류 번호에 맞춰 `docs/stepNN/` 폴더를 사용합니다. 예: `1. 현재 상태와 목표 정리`는 `docs/step01/`, `2. 사용자·시장·학습 콘텐츠 조사`는 `docs/step02/`입니다.
- 해당 카테고리의 세부 항목을 진행할 때 그 폴더 안에 주제를 알아볼 수 있는 Markdown 파일을 만듭니다. 예: `docs/step01/저장소-현황-및-기존-결정.md`.
- 결과물은 검토 가능한 상태로 정리하고 체크리스트의 해당 항목과 결정 기록을 갱신합니다. 검토나 합의가 남아 있으면 완료로 체크하지 않습니다.
- 한 세부 항목의 작업은 해당 카테고리 폴더 안의 관련 문서에 이어서 기록해도 됩니다. 여러 주제가 독립적으로 검토될 때는 파일을 나눕니다.
- 기존 문서가 다른 경로에 있더라도 새 작업 결과물은 해당 카테고리 폴더에 두고, 필요하면 기존 문서에 연결하거나 반영합니다.

## 진행 현황

- **현재 단계:** 2단계 — 사용자·시장·학습 콘텐츠 조사
- **현재 상태:** 공개 자료와 저장소 문서 기반 조사 초안 작성 완료 — [2단계 조사 문서](../step02/사용자-시장-및-학습콘텐츠-조사.md). 학생·보호자 조사, 콘텐츠 권한 확인, 첫 핵심 사용자 합의 대기. 1단계의 제약·지표·목표 합의도 미완료이며 사용자 요청에 따라 2단계 조사를 먼저 진행함.
- **단계 번호 참고:** 이 체크리스트는 `1단계=현재 상태·목표`, `2단계=사용자·시장·학습 콘텐츠 조사`로 관리합니다. [전체 진행 절차](전체-진행-절차.md)는 같은 내용을 0·1단계부터 세어 번호가 하나씩 어긋나므로, 이후 문서 정합성 작업에서 맞춥니다.
- **완료 표시 기준:** 결과물을 검토하고 해당 단계의 완료 기준에 합의했을 때 체크합니다.
- **체크 방법:** 작업 완료 후 `- [ ]`를 `- [x]`로 바꾸고, 필요한 경우 산출물 링크나 결정 날짜를 덧붙입니다.

- [x] 전문가 에이전트 역할과 협업 규칙을 정의한다
- [x] 기획·학습 설계·UX/UI·아키텍처·프론트엔드·백엔드·QA 관점의 기존 문서 1차 검토를 받는다
- [x] 기존 문서의 확정 사항, 가정, 미결정 사항을 목록화한다 — [현황·목표·정보구조 초안](../step01/현황-목표-및-정보구조.md)

## 1. 현재 상태와 목표 정리

- [x] 저장소의 문서와 실제 구현 상태를 확인한다 — [현황·목표·정보구조 초안](../step01/현황-목표-및-정보구조.md)
- [x] 현재 확정된 결정과 검토가 필요한 가정을 구분한다 — [현황·목표·정보구조 초안](../step01/현황-목표-및-정보구조.md)
- [x] 서비스가 해결할 사용자 문제와 목표를 한 문단으로 정리한다 — 사용자 제공 목표를 기록함
- [ ] 프로젝트 제약을 정리한다: 일정, 예산, 콘텐츠, 기술, 운영 인력
- [ ] MVP 성공·실패를 판단할 초기 신호를 정한다
- [ ] 1단계 결과를 검토하고 사용자와 합의한다

## 2. 사용자·시장·학습 콘텐츠 조사

- [ ] 주요 사용자 유형과 학습 환경을 정리한다
- [ ] 학생의 매일 학습 동기와 중단 요인을 조사한다
- [ ] 첫 대상 학년·학습 목적·과목 후보를 정리한다
- [ ] 콘텐츠 공급 후보와 사용 권한·출처 조건을 확인한다
- [ ] 콘텐츠 정확성·연령 적합성·교육과정 연계 기준을 조사한다
- [ ] 확인된 사실, 가설, 미확인 사항을 분리한다
- [ ] 제품 기획자와 교육·학습 설계자가 사용자 시나리오 및 학습 목표를 제안한다
- [ ] 조사 결과와 첫 핵심 사용자에 합의한다

## 3. 제품 범위와 MVP 결정

- [ ] 첫 출시에서 검증할 핵심 가설을 정한다
- [ ] 핵심 사용자 여정을 정한다: 오늘 자료 확인 → 학습 → 이해 확인 → 완료
- [ ] 기능을 MVP 필수·후속·제외 범위로 나눈다
- [ ] 첫 출시 과목·콘텐츠 형식·하루 학습 분량을 정한다
- [ ] 자료를 고르는 방식과 개인화 필요 여부를 정한다
- [ ] 계정·알림·보상·AI 생성·외부 자료 활용의 MVP 포함 여부를 결정한다
- [ ] 성공 지표와 측정 기준을 정한다
- [ ] MVP 범위와 제외 범위에 합의한다

## 4. 요구사항과 운영 정책

- [ ] 기능 요구사항을 사용자 흐름별로 작성한다
- [ ] 응답성·안정성·접근성·보안 등 품질 요구사항을 정한다
- [ ] 학습 완료와 학습 기록의 기준을 정한다
- [ ] 콘텐츠 단위·난이도·정답·해설·출처·상태 필드를 정한다
- [ ] 게시 가능한 콘텐츠의 검수 조건을 정한다
- [ ] 자료 없음·중복·오답·로드 실패·생성 실패 시 동작을 정한다
- [ ] 개인정보 수집 최소화·보관·삭제·동의 정책을 검토한다
- [ ] 각 요구사항에 확인 가능한 인수 기준을 작성한다
- [ ] 요구사항과 정책을 검토하고 합의한다

## 5. UX/UI 및 화면 설계

- [ ] MVP에 필요한 화면만 기존 화면 설계에서 추린다
- [ ] 오늘 학습 시작부터 완료까지의 화면 흐름을 그린다
- [ ] 로딩·빈 상태·오류·성공·오답 상태를 설계한다
- [ ] 모바일 화면과 반응형 동작을 검토한다
- [ ] 키보드·스크린 리더·색상 대비·터치 영역 기준을 확인한다
- [ ] 학생이 학습 중 막히거나 자료가 없을 때의 대안을 설계한다
- [ ] 와이어프레임 또는 프로토타입을 검토하고 수정한다
- [ ] MVP 화면 흐름과 UX 기준에 합의한다

## 6. 기술·데이터 설계

- [ ] 기존 아키텍처 초안을 MVP 요구사항과 대조한다
- [ ] 프론트엔드·백엔드·콘텐츠 운영 경계를 정한다
- [ ] 핵심 사용자 여정에 필요한 데이터와 API를 설계한다
- [ ] 데이터 모델과 콘텐츠 버전·검수·게시 상태를 정한다
- [ ] 인증·권한·개인정보·로그·비밀정보 처리 방식을 정한다
- [ ] 매일 자료 공급·게시·중복 방지·실패 대체 방식을 정한다
- [ ] AI·TTS·외부 자료 공급자의 필요성·비용·권한·대체 방식을 검토한다
- [ ] 기술 스택과 버전을 요구사항 및 운영 제약에 맞게 확정한다
- [ ] 백업·모니터링·장애 복구 범위를 설계한다
- [ ] 아키텍처·ERD·API 명세를 검토하고 합의한다

## 7. 개발 기반 구축

- [ ] 저장소 구조와 로컬 실행 방법을 정한다
- [ ] 프론트엔드 프로젝트 기반을 구축한다
- [ ] 백엔드 프로젝트 기반을 구축한다
- [ ] 개발·테스트·운영 환경 설정을 분리한다
- [ ] 비밀정보를 코드와 분리한다
- [ ] 데이터베이스 초기화 및 마이그레이션 방식을 마련한다
- [ ] 공통 오류 처리·로그·헬스 체크를 구성한다
- [ ] 합의된 자동화 검증과 빌드 실행 방법을 마련한다
- [ ] 기본 화면과 API 연결을 확인한다
- [ ] 새 개발 환경에서 재현 가능한 실행 안내를 작성한다

## 8. MVP 기능 구현

- [ ] 오늘의 학습 자료 조회 기능
- [ ] 학습 자료 상세 보기 및 학습 진행 기능
- [ ] 학습 완료 기록 및 중복 기록 방지
- [ ] 퀴즈 풀이·채점·해설 기능
- [ ] 학습 결과와 필요한 사용자 기록 저장
- [ ] 관리자 콘텐츠 작성·수정 기능
- [ ] 관리자 검수·승인·반려·게시 기능
- [ ] 콘텐츠가 없거나 요청에 실패했을 때의 대체 흐름
- [ ] 기능별 인수 기준 및 검증 결과 기록
- [ ] MVP 범위의 모든 핵심 기능을 통합 검토

## 9. 콘텐츠 공급과 품질 관리

- [ ] 직접 작성·AI 보조·제휴·외부 자료 중 공급 방식을 결정한다
- [ ] 출처 및 사용 권한을 기록하는 방식을 정한다
- [ ] 학습 목표·정확성·정답·해설·난이도 검수 기준을 마련한다
- [ ] 연령 적합성·편향·부적절 표현 점검 기준을 마련한다
- [ ] 검수 전 콘텐츠가 학생에게 노출되지 않는지 확인한다
- [ ] 중복 확인·수정 이력·승인/반려 사유를 관리한다
- [ ] 실제 샘플 콘텐츠를 준비하고 검수한다
- [ ] 매일 자료 공급 실패 시 운영 절차와 대체 콘텐츠를 마련한다
- [ ] 샘플 게시부터 학생 화면 제공까지 흐름을 확인한다

## 10. 통합 검증과 사용성 확인

- [ ] 요구사항과 인수 기준에 따라 핵심 여정을 확인한다
- [ ] 오늘 자료 정상 조회·자료 없음·로드 실패 흐름을 확인한다
- [ ] 학습 완료 기록과 중복 제출 동작을 확인한다
- [ ] 퀴즈 정답·오답·재시도·결과 보존을 확인한다
- [ ] 미검수 콘텐츠 비노출과 관리자 승인 흐름을 확인한다
- [ ] 학생·관리자 권한 경계를 확인한다
- [ ] 모바일 화면·키보드 조작·접근성을 확인한다
- [ ] 콘텐츠 정확성·출처·연령 적합성을 검수한다
- [ ] 사용자 피드백 및 결함을 기록하고 우선순위를 정한다
- [ ] 출시 차단 결함을 해결하거나 출시 결정과 잔여 위험을 문서화한다

## 11. 출시 준비와 배포

- [ ] 운영 환경·도메인·HTTPS를 준비한다
- [ ] 운영 비밀정보와 접근 권한을 설정한다
- [ ] 데이터베이스 백업과 복구 절차를 확인한다
- [ ] 배포·마이그레이션·롤백 절차를 작성한다
- [ ] 서비스 상태·오류·자료 공급·외부 API 비용 모니터링을 준비한다
- [ ] 장애 대응 담당과 연락 절차를 정한다
- [ ] 단계적 공개 또는 제한 사용자 공개 방식을 결정한다
- [ ] 배포 후 로그인/접속·오늘 자료·학습 완료 흐름을 점검한다
- [ ] 출시 결과와 운영 이슈를 기록한다

## 12. 운영과 개선

- [ ] 자료 생성·검수·게시·제공 성공 여부를 정기 확인한다
- [ ] 학습 시작·완료·재방문 등 합의한 지표를 확인한다
- [ ] 오류 신고와 학생·보호자 피드백을 검토한다
- [ ] 콘텐츠 품질 문제와 UX·기술 문제를 분류한다
- [ ] 개선 가설과 우선순위를 정한다
- [ ] 다음 개선 주기의 범위와 완료 기준을 정한다
- [ ] 개선 후 지표와 피드백 변화를 확인하고 기록한다
