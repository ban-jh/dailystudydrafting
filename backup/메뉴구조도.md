# Daily Study 메뉴 구조도 및 화면 기능

> 관리자·학생 학습 콘텐츠 기획과 기존 아키텍처 경로를 함께 반영한 메뉴 설계안입니다. 사용자 공간을 학생·학부모로 나누고, 관리자 공간은 기초정보부터 콘텐츠 검수와 일정 게시까지 이어지도록 구성했습니다. 제안 경로 중 미구현 항목은 구현 시 라우트와 API를 추가해야 합니다.

## 1. 메뉴 구조도

서비스 화면은 하나의 역할 혼합 메뉴로 그리지 않고, 별도의 사용자 FE와 관리자 FE 메뉴도로 관리합니다. 사용자 FE 아래에 학생과 학부모를 나누고, 두 화면은 각각 사용자 BE API에 연결합니다. 관리자 FE는 관리자 BE API에 연결합니다.

### 1.1 사용자 메뉴도 — 사용자 FE

~~~text
사용자 FE
├── 공통 진입
│   ├── 로그인 (/login)
│   ├── 회원가입 (/signup)
├── 시스템 안내
│   └── 이용 기간 만료 (/access-expired)
├── 학생 (STUDENT)
│   ├── 오늘 (/dashboard)
│   ├── 과목별 학습 (/subjects)
│   │   ├── 과목 선택·필터
│   │   ├── 교과서 단원별 게시 세션 목록
│   │   ├── 학습 세션 (/study-sessions/:sessionId)
│   │   └── 개인 복습 (/review/:reviewId)
│   ├── 주간 계획 (/schedule/week)
│   ├── 학습 기록 (/learning-records)
│   └── 내 정보 (/mypage)
└── 학부모 (PARENT)
    ├── 자녀 현황 (/parent/dashboard)
    ├── 자녀별 과목 진도 (/parent/children/:childId/progress)
    ├── 자녀 주간 계획 (/parent/children/:childId/schedule)
    ├── 자녀 학습 기록·성취도 (/parent/children/:childId/activity)
    ├── 자녀 연결·전환 (/parent/children)
    └── 보호자 정보 (/parent/profile)
~~~

학생은 과목 → 단원 → 게시 세션 순으로 학습을 탐색합니다. 주간 계획은 날짜별 분량과 복습을 확인하는 보조 화면입니다. 학부모는 연결·동의된 자녀의 정보를 읽기 전용으로 확인합니다.

### 1.2 관리자 메뉴도 — 관리자 FE

~~~text
관리자 FE (ADMIN)
├── 운영 요약 (/admin)
├── 기초정보
│   ├── 학교 관리 (/admin/schools)
│   └── 학과 편성 (/admin/curriculum)
├── 학습 세션·콘텐츠
│   ├── 세션·단계 콘텐츠 구성 (/admin/sessions)
│   ├── 콘텐츠 라이브러리 (/admin/contents)
│   └── 검수·승인 (/admin/reviews)
├── 학습 일정
│   ├── 일정 준비도·목록 (/admin/schedules)
│   ├── 일·주간 편성 (/admin/schedules/new)
│   ├── 게시·변경 이력 (/admin/schedules/:scheduleId)
│   └── 학생 진행 현황 (/admin/schedules/:scheduleId/progress)
├── 학생·계정 운영
│   ├── 학생 배정·학습 시작점 (/admin/students)
│   ├── 사용자·역할 관리 (/admin/users)
│   ├── 학생·보호자 연결 관리 (/admin/parent-links)
│   └── 이용 권한·기간 관리 (/admin/access)
├── 시스템 관리
│   ├── 관리자 계정·역할·권한 (/admin/system/admins, /admin/system/roles)
│   └── 공통 코드 관리 (/admin/system/common-codes)
└── 운영 통계 (/admin/stats)
~~~

관리자는 학교를 등록한 뒤 학과 편성에서 학년도·학교·학년·학기별 편성 목록을 관리합니다. 상세 화면의 왼쪽 과목 목록에서 과목을 선택하고 오른쪽에서 과목·출판사·교과서 판본·목차를 함께 설정한 뒤, 단원별 세션과 단계 콘텐츠를 구성·검수하고 일정으로 게시합니다. 공통 사전이나 전역 학습 목표 매핑은 별도 메뉴에 두지 않습니다. 중학교·고등학교 학년은 공통 코드의 고정값(각 1·2·3학년)을 사용하고 별도 학년 생성·삭제는 하지 않습니다. 운영자는 학과 편성 화면에서 학년과 과목을 함께 관리합니다. 학습 목표 문장은 세션에 직접 입력합니다. 권한 운영은 관리자 계정·역할과 학교 범위를 관리하는 시스템 관리 메뉴에서, 학생·학부모의 서비스 이용 상태와 만료일은 학생·계정 운영 메뉴에서 처리합니다. 공통 코드는 학년 코드와 실제 운영에 반복 사용되는 상태·유형 값을 제공합니다. 학년 코드는 시스템 고정값이며 학교별 운영자가 변경하지 않습니다. 이는 교육 콘텐츠 사전이나 학습 목표 분류를 추가하는 의미가 아닙니다.

### 1.3 4개 서버 역할 경계

| 서버 | 담당 범위 |
|---|---|
| 사용자 FE | 학생·학부모 메뉴, 역할별 화면, 과목별 세션 탐색, 학습·복습 수행, 보호자 조회 화면, 이용 만료 안내 |
| 사용자 BE | 학생에게 게시·배정된 일정·세션·콘텐츠 제공, 학습 진행·복습·기록 저장, 보호자 연결 범위와 사용자 이용 기간·상태 검증 |
| 관리자 FE | 기초정보 등록, 세션·콘텐츠 작성·검수, 일정 편성·게시, 관리자 역할·권한·학교 범위, 사용자 이용 기간, 공통 코드 운영 화면 |
| 관리자 BE | 교육과정·콘텐츠·일정 관리, 관리자 세부 권한·범위 판정, 사용자 이용 권한·기간 관리, 공통 코드 계약·감사 기록 |

두 FE는 역할별로 분리 배포하고 각기 대응하는 BE를 호출합니다. 사용자 BE는 승인·게시된 학생 배정 데이터만 제공하며 관리자 초안과 검수 대기 자료를 반환하지 않습니다. 두 BE 모두 인증 주체와 역할을 확인하고, 사용자 BE는 학생 본인 및 보호자-자녀 연결 범위를 강제합니다. 관리자 BE는 관리자 역할과 학교 권한 범위를 검증합니다.

로그인 후 STUDENT/PARENT는 사용자 FE의 해당 화면으로, ADMIN은 관리자 FE의 운영 요약으로 이동합니다. 보호된 경로와 BE API 모두 역할 및 데이터 범위를 검증합니다.

## 2. 공통 화면 및 인증

| 화면 | 경로 | 주요 기능 |
|---|---|---|
| 로그인 | `/login` | 학생·학부모·관리자가 로그인합니다. 인증된 사용자 역할에 맞는 시작 화면으로 이동합니다. |
| 회원가입 | `/signup` | 신규 계정 가입 정보를 입력합니다. 학생·학부모 계정의 가입 및 자녀 연결 절차가 필요합니다. 관리자 계정은 시스템 운영 정책에 따른 별도 생성 방식을 권장합니다. |

로그인/회원가입은 중앙 정렬형 인증 레이아웃을 사용합니다. 라우터 가드가 세션을 확인하며, API 응답이 401이면 토큰 갱신을 시도하고 실패하면 로그아웃 후 로그인 화면으로 이동합니다. Google·Kakao 소셜 로그인은 Phase 2 범위입니다.

## 3. 사용자 화면 — 학생 (STUDENT)

학생의 주 메뉴는 오늘, 과목별 학습, 주간 계획, 학습 기록입니다. 학습 세션 안에서 관리자가 게시한 개념 자료·핵심 요점·기초 연습·적용 문제·복습 활동을 제공합니다.

| 메뉴 / 화면 | 경로 | 화면 기능 |
|---|---|---|
| 오늘 | /dashboard | 오늘 배정된 새 학습과 복습, 진행 중 학습 이어하기, 예상 분량을 요약합니다. |
| 과목별 학습 | /subjects | 학생에게 배정된 과목별로 게시된 학습을 교과서 단원 순으로 탐색합니다. 학기·단원·상태 필터와 제목 검색을 제공합니다. |
| 단원별 세션 목록 | /subjects/:subjectId/units/:unitId/sessions | 목차 계층과 세션명, 목표, 상태, 예정일, 예상 시간을 표시합니다. |
| 학습 세션 | /study-sessions/:sessionId | 승인 콘텐츠로 선수 확인→개념·예시→회상·요점→기초 연습→독립 적용→마무리를 진행하고 중단 지점부터 이어갑니다. |
| 개인 복습 | /review/:reviewId | 오답·힌트·회상 결과에 따른 복습을 수행하고 복습 이유와 원 학습 세션을 확인합니다. |
| 주간 계획 | /schedule/week | 날짜별 새 학습·공통 복습·개인 복습과 분량을 확인합니다. 과목별 전체 목록을 대신하지 않습니다. |
| 학습 기록 | /learning-records | 완료 세션, 이어할 학습, 복습 필요 항목과 과목별 진행을 확인합니다. |
| 내 정보 | /mypage | 프로필·계정과 허용된 개인 설정을 관리합니다. |

과목별 목록의 전체는 학생에게 배정되고 게시된 세션 전체입니다. 관리자 초안·검수 대기·미게시 콘텐츠는 노출하지 않습니다. 예정일 전 학습은 운영 정책에 따라 예정 또는 잠금 상태로 표시합니다. 진행 집계와 복습 연결은 목표 문구가 아니라 세션 ID를 기준으로 합니다.

실생활 영어와 배지·포인트 등은 후속 범위로 두고 주 학습 메뉴와 구분합니다.

## 4. 사용자 화면 — 학부모 (PARENT)

학부모는 연결·동의된 자녀의 학습 상태를 읽기 전용으로 확인합니다. 여러 자녀가 있으면 자녀를 선택한 뒤 해당 자녀의 정보만 조회합니다.

| 메뉴 / 화면 | 경로 | 화면 기능 |
|---|---|---|
| 자녀 현황 | /parent/dashboard | 오늘의 학습 배정·진행·완료, 복습 필요 항목과 최근 활동을 요약합니다. |
| 자녀별 과목 진도 | /parent/children/:childId/progress | 학교·학년도·과목·교과서 단원별 게시 세션과 진행 상태를 확인합니다. |
| 자녀 주간 계획 | /parent/children/:childId/schedule | 날짜별 새 학습·복습과 예상 분량·완료 여부를 확인합니다. |
| 자녀 학습 기록·성취도 | /parent/children/:childId/activity | 기간·과목별 학습 완료와 허용된 풀이·복습 결과 요약을 확인합니다. 개별 답안 공개는 별도 정책을 따릅니다. |
| 자녀 연결·전환 | /parent/children | 자녀 연결·동의 상태와 여러 자녀 간 전환을 관리합니다. |
| 보호자 정보 | /parent/profile | 보호자 계정 정보를 관리합니다. |

자녀 연결·동의 및 해제, 복수 자녀 정책이 필요합니다. 서버는 매 요청마다 보호자와 자녀의 연결 권한을 확인합니다. 학습 수행·답안 제출·콘텐츠 편집 권한은 제공하지 않습니다.

## 5. 관리자 화면 — ADMIN

관리자는 운영 요약에서 시작해 기초정보를 설정하고, 단원별 세션·콘텐츠를 검수한 뒤 학생 일정으로 게시합니다. 관리자 레이아웃과 ADMIN 권한을 사용합니다.

| 메뉴 / 화면 | 경로 | 화면 기능 |
|---|---|---|
| 운영 요약 | /admin | 학교·학년도·학년의 과목·교과서·목차 준비, 세션 검수, 일정 초안을 요약하고 누락된 설정으로 이동합니다. |
| 학교 관리 | /admin/schools | 학교명·학교급과 운영 상태를 관리합니다. 지역·학교 코드는 필요할 때 선택 입력합니다. |
| 학과 편성 | /admin/curriculum | 학년도·학교·학년·학기별 과목 편성을 목록으로 관리합니다. 상세에서 왼쪽 과목을 고르고 오른쪽에 출판사와 단원별 목차 행(요약·연결 문제·성취 기준·상태)을 관리합니다. 학년은 학교급별 고정 공통 코드입니다. |
| 세션·단계 콘텐츠 구성 | /admin/sessions | 목차 단원별 세션을 만들고 학생용 목표 문장 하나와 단계별 자료·문항·정답·해설을 구성합니다. |
| 콘텐츠 라이브러리 | /admin/contents | 자료·문제의 출처·버전·대상·검수 상태를 검색·작성·수정합니다. AI 생성·허용된 자료 수집·직접 작성은 초안으로 등록합니다. |
| 검수·승인 | /admin/reviews | 정확성·학년 적합성·해설·출처·세션 목표 정합성을 검토해 승인·반려합니다. 승인 버전만 학생 일정에 연결합니다. |
| 일정 준비도·목록 | /admin/schedules | 학교·학년도·학년·과목별 준비 상태와 초안·게시 상태를 확인합니다. |
| 일·주간 일정 편성 | /admin/schedules/new | 대상과 세션을 선택해 날짜별 새 학습·공통 복습, 분량과 미리보기를 구성합니다. 목표 누락이나 필수 콘텐츠 미승인 시 게시를 막습니다. |
| 게시·변경 이력 | /admin/schedules/:scheduleId | 학생 미리보기 후 게시하고 게시 버전·변경 범위·감사 이력을 확인합니다. 완료 기록은 보존합니다. |
| 학생 진행 현황 | /admin/schedules/:scheduleId/progress | 학습 시작·완료, 복습 상태, 단계별 이탈과 세션 ID별 학습 신호를 집계합니다. |
| 학생 배정·계정 관리 | /admin/students, /admin/users | 일정 대상을 배정하고 역할·계정·학생 보호자 연결을 운영합니다. |
| 운영 통계 | /admin/stats | 플랫폼 사용자·학습·콘텐츠 운영 지표를 확인합니다. MVP 핵심 흐름 이후 확장합니다. |

**공통 선택값과 목표:** 공통 사전이나 전역 학습 목표 매핑은 관리자 메뉴에 두지 않습니다. 반복 선택값은 내부 ID와 시스템 목록으로 표준화하며 목록에 없는 출판사 등은 운영자가 추가한 뒤 사용합니다. 목표 문장은 세션에 직접 입력하고 MVP에서는 세션당 목표 하나, 집계 키는 세션 ID로 둡니다.

**게시 시점 고정:** 학교·학년도·학년/과목 편성, 교과서 판본, 목차 단원, 세션 ID·목표 문장, 단계 콘텐츠 버전을 게시 일정에 고정합니다. 게시 이후 편집은 새 버전으로 처리하고 이전 학습 기록을 보존합니다.

### 사용자 이용 기간 만료 처리

사용자 계정 또는 배정 단위에 이용 시작일·종료일을 설정합니다. 종료일은 Asia/Seoul 기준 해당 날짜 23:59:59까지 유효하며, 종료 시각 이후 사용자 FE의 보호 화면은 /access-expired 안내 페이지로 이동하고 사용자 BE도 403 ACCESS_EXPIRED를 반환합니다. 만료 안내 페이지에는 만료일, 이용 제한 안내, 관리자/학교 문의 경로를 표시하고 로그아웃은 계속 사용할 수 있게 합니다. 운영자가 연장 또는 계정 상태 복구를 하면 다시 접근할 수 있습니다. API 검증은 서버가 기준이며 프런트 경로 이동만으로 제한하지 않습니다.

## 6. 사용자 접근 권한

| 기능 영역 | 비로그인 | 학생 (STUDENT) | 학부모 (PARENT) | 관리자 (ADMIN) |

| 세션 학습·복습 제출 | 불가 | 본인 학습 수행 | 불가 | 검수·운영 목적 조회 |
| 주간 계획 | 불가 | 본인 게시 일정 | 연결 자녀 일정 읽기 | 편성·게시·변경 |
| 학습 기록·진행 지표 | 불가 | 본인 기록 | 연결 자녀의 허용 요약 | 학생·학교 범위 집계 |

## 9. 설계상 참고 사항

- 이 메뉴 구조는 최신 학습 운영 기획을 반영한 제안입니다. 경로 중 기존 라우터에 없는 항목은 구현 시 등록하고 API·권한을 추가해야 합니다.
- 사용자 화면의 게시 콘텐츠와 필터 결과는 학생의 학교·학년도·학년 배정 범위로 제한합니다.
- 관리자 세션 목표는 세션별 직접 입력값입니다. 공통 목표 사전, 교과서 간 목표 매핑, 관리자 편집용 공통 사전 화면은 MVP 메뉴에 포함하지 않습니다.
- 배지·포인트·랭킹·학습 캘린더 등 Phase 3 기능은 관련 API나 데이터 도메인이 정의돼 있지만, 현재 라우터에 별도 화면 경로는 등록되어 있지 않습니다. 따라서 별도 메뉴로 확장할 때 화면 라우트를 추가해야 합니다.
- 관리자 권한 메뉴, 공통 코드 관리 및 사용자 이용기간 만료 화면/API는 신규 제안입니다. 구현 시 FE뿐 아니라 BE 권한·기간 검사를 함께 추가해야 합니다.
- 학생-학부모 관계, 동의·연결 절차, 자녀별 데이터 조회 API, 콘텐츠 할당 관계와 대상자 조회 API는 기존 문서에서 구체적으로 정의되지 않아 후속 설계 항목입니다.
- 반복 선택값은 내부 ID와 시스템 목록으로 표준화합니다. 목록에 없는 출판사 등은 운영자가 추가한 뒤 선택할 수 있습니다.
- 학생별 시작 단원과 skip/복구를 후속 기능으로 구현한다면 개인 학습 진도에 저장하고 공통 일정이나 다른 학생의 진도와 분리합니다.
- API 표에서 회원가입·프로필·설정 등 일부 기능의 제공 단계가 정해져 있더라도, 화면 표에서는 해당 기능과 관련된 API 및 도메인 설명을 함께 참고했습니다.
