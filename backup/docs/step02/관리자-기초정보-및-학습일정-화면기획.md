# 관리자 기초정보·학습일정 화면 상세 기획

> 상태: 관리자 전용 화면 설계 초안. 기존 시스템 문서의 학교·교육과정 관리 방향을 실제 화면 흐름과 일정 편성 선행 조건으로 구체화합니다.
>
> 기준일: 2026-11-06
>
> 화면 프로토타입: [관리자 기초정보·학습 일정 프로토타입](../../screen-spec/admin-learning-planner.html)
>
> 범위: 학교/학년도/학년 과목 구성 → 교과서/판본 → 단원 목차 → 학습 세션·콘텐츠 → 일정 편성·게시 → 학생 진행 모니터링.

## 1. 기존 설계 검토와 보완점

저장소의 [관리자 기능 설계](../../study_admin.md)에는 학교·교육과정 관리, 학교/학년별 과목·출판사 편성, 교과서 단원 매핑, 공통 과목·단원 관리가 이미 개념적으로 포함되어 있습니다. [업무 흐름 설계](../../study_process.md)도 학교·학년·과목·출판사·단원 설정을 일정 편성보다 앞에 둡니다.

다만 직전에 만든 [학습 화면 프로토타입](../../screen-spec/learning-process.html)의 관리자 화면은 학교·학년·과목을 선택 필터로만 두고, 해당 정보를 등록·검증·버전 관리한 뒤 일정을 편성하는 실제 선행 화면을 구현하지 않았습니다. 그래서 프로토타입 단독으로 보면 사용자가 짚은 것처럼 준비 데이터가 없는 상태에서 일정부터 편성하는 모습입니다. 이 문서는 그 누락을 보완해 관리자를 위한 별도 화면 사양으로 정리합니다.

## 2. 운영 원칙 및 데이터 계층

### 2.1 계층

```text
학교
└── 학년도
    └── 학년도별 운영 학년
        └── 학년별 개설 과목
            └── 사용 교과서(출판사·저자·판본·학기)
                └── 교과서 단원 목차(대단원·중단원·소단원)
                    └── 학습 세션(목표 문장 + 단계별 콘텐츠 및 검수 버전)
                        └── 일/주간 학습 일정
                            └── 대상 그룹·학생 배정 및 학습 기록
```

MVP 일정의 대상 과목은 확인된 교과서 판본이 있는 경우로 제한합니다. 교과서가 없는 과목은 운영 요구가 확인된 뒤 별도 예외 흐름으로 추가합니다. 학교는 여러 개의 학년도 편성을 갖습니다. 적용 중인 편성은 기준일에 학생을 연결하는 데 사용하고, 이전 학년도 편성과 학습 이력은 보존합니다. 과목명이나 단원명이 같더라도 교과서와 연도가 다르면 서로 다른 편성으로 관리합니다.

### 2.2 기준 데이터와 학교별 편성 구분

- **운영 기초정보:** 학교, 학년도·학년, 학교에서 실제 개설한 과목, 사용하는 교과서 판본, 확인된 목차.
- **학습 세션·콘텐츠:** 단원별 세션에 목표 문장을 직접 기록하고, 목표에 맞는 개념 자료·요점·연습·적용 문제와 해설을 함께 둡니다.
- **일정/배정:** 날짜 또는 주차별 세션, 공통 대상, 학생별 개인 복습, 공개 상태.

공통 사전은 여러 학교의 표기와 중복을 통일해 데이터 정합성·재사용·통계를 지원합니다. 다만 MVP는 별도 편집 화면 없이 내부 ID와 기본 선택 목록으로 중복을 막습니다. 목록에 없는 출판사 등은 운영자가 목록에 추가한 뒤 선택하게 합니다. 학습 목표 문장은 세션마다 하나씩 직접 입력하고, 목표별 집계가 필요하면 자유 문장 대신 세션 ID를 사용합니다. 공통 분류/매핑 UI는 다학교 비교나 공용 콘텐츠 재사용이 필요해질 때 검토합니다.

### 2.3 일정 생성 진입 조건

관리자가 일정을 만들 때 시스템은 다음을 확인합니다.

1. 학교와 대상 학년, 학년의 적용 학년도가 활성 상태.
2. 대상 학년의 과목 편성이 등록되고 적용 상태.
3. MVP에서는 과목에 확인된 교과서 판본과 목차가 반드시 연결됨. 교과서가 없는 과목은 일정 편성 대상으로 허용하지 않음.
4. 선택한 세션에 학생용 목표 문장이 하나 입력됨. MVP에서는 세션 하나당 목표 하나로 제한하고, 진행·복습 집계는 자유 문장이 아니라 세션 ID를 기준으로 함.
5. 각 필수 학습 단계에 게시 가능한 검수 완료 콘텐츠가 연결됨.
6. 예상 시간, 공개일, 배정 대상이 유효함.

조건 미충족 시 일정 저장은 초안으로만 가능하며 게시를 차단합니다. 각 오류에는 해당 기초정보 편집 화면 바로가기와 누락 건수를 표시합니다.

## 3. 관리자 내비게이션 구조

```text
관리자
├── 운영 요약
├── 기초정보
│   ├── 학교 목록/상세
│   └── 학과 편성
├── 콘텐츠 운영
│   ├── 콘텐츠 라이브러리
│   ├── 콘텐츠 작성/가져오기
│   └── 검수·승인
├── 학습 일정
│   ├── 일정 준비도
│   ├── 일/주간 편성
│   ├── 게시/변경 이력
│   └── 학생 진행 현황
├── 학생·계정 운영
│   ├── 학생 배정 및 학습 시작점
│   ├── 사용자 역할·이용 권한·기간
│   └── 학생·보호자 연결 관리
└── 시스템 관리
    ├── 관리자 계정·역할·세부 권한
    └── 공통 코드 관리
```

상단 컨텍스트 바에 현재 학교, 학년도, 학년 및 로그인 관리자 권한 범위를 표시합니다. 공통 선택값에는 학교급별 고정 학년 코드(중1~중3, 고1~고3)가 포함됩니다. 학년은 별도로 추가하지 않고, 실제 학교 과목·교과서·목차는 학년도 화면의 학년 선택 컨텍스트에서 편성합니다. 관리자에게 필요한 권한만 메뉴/API에 부여하고, 사용자 이용 기간은 학생·계정 운영에서 관리합니다.

**공통 사전이 필요한 이유와 MVP 판단:** 여러 학교가 서로 다른 표기와 중복 항목을 만들지 않게 해 데이터 정합성, 재사용, 학교 간 통계를 지원합니다. 현재 한 학교 중심 MVP에서 편집 화면은 추가 업무가 되므로 시스템 기본값으로 관리합니다. 다학교 운영, 재사용 콘텐츠 검색, 표준 기반 비교가 필요해질 때 사용자 관리 화면을 검토합니다.

## 4. 화면 상세 사양

### ADM-M01 운영 요약 (`/admin`)

**목적:** 일정 편성 전에 어느 기초 데이터가 준비되었는지 알려줍니다.

**화면 배치**

- 상단 컨텍스트: 학교 선택, 학년도 선택, 관리자 계정/권한.
- 준비도 카드: 학교 정보, 학년도 적용, 과목 편성, 교과서/목차 등록, 세션·콘텐츠 검수, 게시 가능한 일정.
- 알림 목록: `2학년 수학 교과서 목차 3개 소단원 누락`, `영어 과목 출판사 미지정`, `세션 '연립방정식의 해 판별' 콘텐츠 검수 대기`.
- 빠른 작업 버튼: `학교 등록`, `과목 편성`, `교과서 추가`, `목차 가져오기`, `일정 만들기`.
- 최근 변경/게시/검수 이력.

**행동:** 준비도 카드 선택 시 누락된 설정 화면과 필터를 연다. 일정 만들기 버튼은 모든 필수 데이터가 준비되지 않으면 차단 이유와 선행 작업을 안내합니다.

### ADM-M02 학교 목록·상세 (`/admin/schools`, `/admin/schools/:schoolId`)

**목록 필드:** 학교명, 교육기관 코드(있을 때), 학교급, 지역, 사용 상태, 활성 학년도, 등록/수정일.

**필수 입력:** 학교명, 학교급. **선택 상세 정보:** 지역, 학교 코드. 시간대는 MVP에서 Asia/Seoul로 고정하며 메모는 등록 화면에서 제외합니다.

**주요 동작:** 검색, 등록, 상세 보기, 비활성화. 학교를 제거하는 대신 비활성화하여 기존 이력을 보존합니다. 학교급 변경은 기존 학년도 편성과 충돌할 수 있으므로 적용 중 편성이 있으면 경고하고 변경을 제한합니다.

**빈/오류 상태:** 학교 미등록이면 첫 학교 등록 CTA, 중복 학교명/코드 가능성 안내, 저장 실패 시 입력값 보존.

### ADM-M03 학과 편성 (/admin/curriculum, 상세 /admin/curriculum/:curriculumId)

**목적:** 학교·학년도·학년·학기별 과목 편성을 한 목록에서 찾고, 과목별 교과서와 목차를 한 상세 화면에서 함께 관리합니다. 학년도 편성, 개설 과목, 출판사·판본, 목차가 여러 메뉴로 분산되지 않게 합니다.

**학년 코드:** 중학교 MIDDLE_1~MIDDLE_3, 고등학교 HIGH_1~HIGH_3의 시스템 고정 공통 코드를 사용합니다. 코드 키·명칭·정렬은 시스템에서 제공하며 관리자가 추가·삭제·변경하지 않습니다. 각 목록 행의 학년은 학교급에 맞는 공통 코드를 사용합니다.

**목록 화면 필터:** 연도/학년도, 학교, 학년, 학기, 상태, 과목명 검색. 목록에는 학년도, 학교, 학년, 학기, 과목 요약, 상태를 표시합니다. 과목 요약은 첫 과목명과 나머지 개수로 표현합니다(예: 국어 외 3개). 행을 선택하거나 상세 버튼을 누르면 해당 편성 상세로 진입합니다.

**목록 필드 예시:** 2026학년도 | 부안중학교 | 중학교 2학년 | 1학기 | 국어 외 3개 | 편성 완료.

**상세 화면 배치:** 상단에는 학교·학년도·학년·학기 및 편성 상태를 고정해 보여줍니다. 본문은 좌우 분할로 구성합니다. 왼쪽 패널에는 해당 학기 과목 목록과 과목 추가/정렬을 둡니다. 과목을 선택하면 오른쪽 패널의 정보가 바뀝니다.

**오른쪽 과목 정보:** 교과서 정보는 출판사만 편집합니다. 교과서명, 저자, 판본, ISBN, 채택 근거 등 나머지 필드는 이 화면에서 관리하지 않습니다. 그 아래 목차는 트리 텍스트가 아니라 단원별 행 테이블로 관리합니다. 각 행은 `unit_id`, `parent_unit_id`(상위 단원, 없으면 NULL), `unit_title`, `unit_number`, `sort_order`, `summary`, `achievement_standard`, `status`를 가집니다. 문제는 문제 본문을 목차 행에 중복 저장하지 않고 `unit_id`를 가진 문항과 연결해 단원별 문제 수/유형을 표시합니다. 화면 열은 순서, 상위 단원, 단원명, 단원 요약, 연결 문제(유형·개수), 성취 기준, 상태로 구성하고 행 추가·수정·정렬·가져오기 미리보기를 지원합니다. 성취도 결과는 학생 풀이 기록을 기준으로 집계하며 목차 행에 학생별 점수를 저장하지 않습니다.

**동작/검증:** 새 편성 생성 시 학교, 학년도, 학년 코드, 학기를 지정합니다. 같은 학교·학년도·학년·학기에 중복 편성을 막습니다. 과목은 한 편성 안에서 중복 등록할 수 없습니다. 교과서 판본·목차는 선택 과목에 소속되며 별도 메뉴나 별도 라우트로 이동하지 않습니다. 적용 상태에서는 최소 하나의 과목을 요구하고, 일정 게시에 사용할 과목은 교과서 판본과 확인된 목차를 연결해야 합니다. 편성/교과서/목차 변경 전에는 연결된 세션·콘텐츠·초안/게시 일정의 영향을 보여주고 이력을 기록합니다.

**화면 이벤트:** 목록에서 상세 클릭 → 좌우 상세 패널 전환. 왼쪽 과목 클릭 → 오른쪽 해당 과목의 출판사와 단원 행 데이터 표시. [과목 추가] → 과목 선택 및 중복 확인. 출판사와 단원 행은 함께 저장하며, 행 추가·파일 가져오기는 저장 전 미리보기를 제공합니다. 게시 참조 중인 목차 행은 하드 삭제하지 않고 종료/대체 처리합니다.

### ADM-M04 학습 세션·콘텐츠 구성

**목적:** 목차 단원마다 실제 학생에게 배정할 학습 활동 묶음을 만듭니다. 별도 전역 목표 분류나 매핑 화면은 두지 않습니다.

**세션 필드:** 세션명, 단원, 학생용 목표 문장, 예상 학습 시간, 순서, 공개 상태. 목표 문장은 학생이 무엇을 설명하거나 풀 수 있는지 관찰 가능한 표현으로 씁니다.

**단계 콘텐츠:** 개념 자료 → 중요 요점/회상 질문 → 기초 연습 → 독립 적용 → 마무리/복습. 단계별 자료·문항·정답/해설·출처를 붙이고 담당 교사가 검수합니다.

### ADM-M05 콘텐츠 라이브러리·검수 (`/admin/contents`, `/admin/reviews`)

**일정에서 필요한 콘텐츠 구조:** 개념 자료, 중요 요점, 기초 문제, 적용 문제, 복습 질문/유사 문항, 정답과 해설. 목표는 별도 매핑하지 않고 세션에 직접 입력합니다. 세션에는 목표 문장, 과목·단원, 대상 학년을 두고 단계별 콘텐츠를 연결합니다. 콘텐츠에는 제목, 유형, 난이도, 예상 시간, 출처/권리 정보, 버전, 작성자, 상태를 둡니다.

**검수 상태:** 초안 → 검수 요청 → 승인 또는 반려. 학생에게는 승인된 게시 버전만 제공합니다. 오답 복습 콘텐츠는 원 문항을 재사용하는지, 변형/유사 문항인지 구분하고 원 출처와 세션 연결을 보존합니다.

**콘텐츠 목록 필터:** 학교/학년, 과목, 교과서 판본, 목차 단원, 세션, 콘텐츠 단계, 검수/게시 상태, 출처.

### ADM-M06 일정 준비도 및 편성 (`/admin/schedules`, `/admin/schedules/new`)

일정 생성은 `대상 → 범위 → 날짜와 반복 → 학습 세션/콘텐츠 → 분량 확인 → 미리보기 → 게시` 단계형 편집으로 설계합니다.

**1 대상 선택:** 학교, 학년도, 학년, 선택적으로 학급/그룹. 선택한 조합의 학생 수와 적용 중 교육과정을 확인합니다.

**2 학습 범위 선택:** 과목 → 적용 교과서 판본 → 목차 단원 → 승인 가능한 학습 세션(목표 문장 포함). 세션 목표가 비었거나 필수 단계 콘텐츠가 미승인인 경우 게시할 수 없음을 표시하고 `기초정보 보완` 링크를 제공합니다.

**3 일정 구성:** 시작/종료일, 주간 반복 요일, 날짜별 새 학습 또는 공통 누적 복습, 시간대/마감(필요 시), 예상 학습 시간. 학생별 오답·간격 복습은 이 공통 계획과 구분해 자동 배정 정책으로 설정합니다.

**4 세션 콘텐츠 배치:** 날짜 카드에 세션과 콘텐츠 단계를 배치합니다. 각 단계에서 승인 상태, 세션 목표와의 적합성, 문항 수, 정답/해설, 예상 시간을 확인합니다. 같은 세션의 단계 순서는 선수 확인→개념→요점/회상→기초→적용→마무리를 기본 순서로 둡니다. 주간 분할 시에는 순서를 유지하며 날짜별로 나눕니다.

**5 사전 검증:** 교육과정 미적용, 교과서 판본 누락, 목차 미확인, 세션 목표 입력 누락, 콘텐츠 검수 대기, 하루 분량 초과, 날짜 중복, 대상 학생 없음 등을 오류/경고로 구분합니다. 오류가 남으면 게시 불가, 경고는 이유 확인 후 게시 확인 절차를 거칩니다.

**6 미리보기/게시:** 실제 학생 역할의 날짜별 화면으로 새 학습과 복습을 미리 봅니다. 게시 후 변경은 변경 요약과 적용 범위를 보여주고 학습 완료·풀이 기록을 보존합니다.

### ADM-M07 일정 상세·학생 진행 현황 (`/admin/schedules/:id`, `/admin/schedules/:id/progress`)

**일정 상세:** 학교/학년도/학년/과목/교과서/단원/세션 ID/목표 문장, 대상, 날짜, 세션·콘텐츠 버전, 게시 상태, 변경 이력을 표시합니다. 목표 문장은 표시용이고 집계 키는 세션 ID입니다. 일정 게시 때 학년도·과목 편성, 교과서 판본, 목차 단원 ID와 이름, 세션 ID·목표 문장, 단계별 콘텐츠 버전을 함께 고정합니다.

**진행 집계:** 대상 학생 수, 날짜별 새 학습 시작/완료, 공통 복습 완료, 개인 복습 예정/지연, 단계별 이탈, 세션별 결과(목표 문장을 함께 표시). 일정이 현재 판본이나 교육과정과 달라진 경우 게시 당시 버전을 계속 표시하고 현재 설정과 비교 경고를 냅니다.

개인 복습 일정은 학생의 응답과 연결되어 있으므로 집계 표와 개인 기록 접근을 구분합니다. 역할 권한에 따라 개인 정보는 제한하고 학년 단위 집계부터 제공합니다.

### ADM-M08 관리자 계정·역할·세부 권한 (/admin/system/admins, /admin/system/roles)

**목적:** 관리자별로 허용할 기능과 학교 범위를 통제하고 권한 변경 이력을 남깁니다.

**관리자 계정 목록:** 이름/이메일, 역할 묶음, 접근 가능한 학교, 계정 상태, 마지막 로그인, 초대 상태. 시스템 관리자가 초대·비활성화·잠금 해제·역할 할당을 수행합니다. 관리자 계정은 공개 회원가입으로 만들지 않습니다.

**역할·권한 편집:** 역할 이름과 권한 코드별 허용 동작을 표로 보여줍니다. 기본 역할은 시스템 관리자, 학교 운영자, 콘텐츠 작성자, 콘텐츠 검수자, 일정 게시자, 조회자입니다. 권한 단위는 학교/교육과정 조회·편집, 콘텐츠 작성, 검수 승인, 일정 편성·게시, 계정 관리, 통계 조회처럼 메뉴가 아니라 실제 API 동작으로 나눕니다. 한 관리자는 복수 역할을 가질 수 있으나 허용 범위의 합집합을 넘지 않습니다.

**범위 제한:** 관리자 계정에 허용 학교를 지정합니다. 모든 학교 권한은 시스템 관리자만 부여할 수 있습니다. UI에서 버튼을 감추는 것과 별개로 관리자 BE가 API마다 권한 코드와 학교 범위를 확인합니다. 게시와 검수는 필요한 경우 다른 담당자로 분리하며 자기 승인 금지 설정을 지원합니다.

**주요 이벤트:** 계정 초대/비활성화, 역할 변경, 학교 범위 변경, 권한 부여/회수. 변경 전·후 값, 수행자, 사유, 시각을 감사 로그에 남기며 자기 권한 상승은 금지합니다. 잠긴 계정의 기존 토큰은 즉시 폐기합니다.

### ADM-M09 사용자 이용 권한·기간 (/admin/access)

**목적:** 학생·학부모의 계정 상태와 유료/학교 제공 이용 기간을 관리하고 만료 전에 운영 조치를 할 수 있게 합니다.

**목록 필드/필터:** 사용자, 역할(STUDENT/PARENT), 학교·학년·학급(해당 시), 이용 상태(예정/이용 중/만료/정지), 시작일, 종료일, 남은 일수. 검색과 기간 임박(예: 7일 이내) 필터를 제공합니다.

**상세/편집:** 학생 또는 보호자 단위 이용 상태, 시작일·종료일, 사유, 적용 범위를 표시합니다. 종료일 입력은 날짜 선택이며 Asia/Seoul 기준 종료일 23:59:59까지 이용 가능, 다음 날 00:00부터 만료 처리합니다. 선택 대상 일괄 연장 전 변경 대상·기존/신규 날짜를 미리 보여주고 확인을 받습니다. 운영 정지와 기간 만료는 서로 다른 상태/사유로 기록합니다.

**만료 처리:** 사용자 BE가 모든 보호 API에서 이용 가능 여부를 검사합니다. 만료 시 403 ACCESS_EXPIRED를 반환하고, 사용자 FE는 현재 학습 진행을 보존한 뒤 /access-expired 안내 화면으로 이동합니다. 안내 화면은 로그인 세션을 유지한 채 만료일, 문의 경로, 로그아웃을 제공하며 학습 데이터는 삭제하지 않습니다. 관리자 연장 반영 후 다시 로그인하거나 재시도하면 원래 화면으로 돌아갑니다. 관리자 FE는 만료 예정 알림과 연장 이력을 제공합니다.

**보호자 계정:** 보호자 본인 이용 기간과 연결된 자녀의 이용 가능 상태를 모두 확인합니다. 보호자에게 자녀 접근이 허용되려면 본인 계정 활성 및 유효 기간, 유효한 자녀 연결, 대상 자녀 이용 허용 상태가 모두 충족되어야 합니다. 운영 정책에 따라 보호자 요약 보기 기간이 학생 학습 기간과 다를 수 있도록 별도 기간 설정이 가능합니다.

### ADM-M10 공통 코드 관리 (/admin/system/common-codes)

**목적:** 여러 화면·서비스가 함께 사용하는 운영 코드의 ID와 표시값을 한곳에서 관리해 FE/BE 간 문자열 중복과 불일치를 막습니다. 이 화면은 교과서 목차나 전역 학습 목표 사전을 관리하는 곳이 아닙니다.

**대상:** 학교급별 고정 학년 코드(MIDDLE_1~3, HIGH_1~3), 사용자/관리자 상태, 이용권 상태, 콘텐츠 유형·검수 상태, 학습 일정 유형, 공통 오류 사유 등 운영 코드. 고정된 시스템 코드와 운영자가 추가할 수 있는 확장 코드를 구분합니다. 권한 코드처럼 보안에 직접 쓰이는 코드는 이름·설명만 관리하고 시스템 키는 변경 불가로 합니다.

**화면/동작:** 코드 그룹 목록, 코드 키, 한국어 라벨, 설명, 정렬 순서, 사용 여부, 시스템 고정 여부, 참조 화면을 표로 표시합니다. 추가·라벨 수정·정렬·비활성화를 지원하고 코드 키 수정 및 참조 중인 코드 삭제는 차단합니다. 변경 시 영향을 받는 API/화면을 표시하고 확인 후 저장합니다.

**개발 공통 관리:** 코드 키는 서버 상수/스키마 계약과 일치하는 안정된 식별자이며 화면 라벨과 분리합니다. API 응답은 code와 displayName을 제공하고 FE는 임의 문자열 비교 대신 공통 타입/클라이언트를 사용합니다. 마이그레이션으로 코드 원본을 배포하고, DB 코드는 운영별 라벨·사용 여부를 유지합니다. FE/BE 공유 계약은 버전 관리되는 공통 API 스키마 또는 공통 패키지에서 관리하고 어느 한 서비스만 수정해 호환성이 깨지지 않도록 합니다.

### 사용자 오류 화면: 이용 기간 만료 (/access-expired)

관리자 메뉴 자체는 아니지만 이용 권한 기능의 필수 사용자 화면입니다. 로그인 여부나 계정 역할과 관계없이 만료된 STUDENT/PARENT가 보호 페이지를 열면 이 안내 화면을 표시합니다. “이용 기간이 종료되었습니다”와 적용 종료일, 학교/운영자 문의 경로, 로그아웃 버튼을 보여줍니다. 오류 화면은 이용권 갱신이나 권한 변경을 직접 수행하지 않습니다. 만료 후에도 저장되지 않은 학습 답안은 서버에 이미 저장된 진행만 보존하고, 화면 이동 전에 제출되지 않은 입력을 임의 제출하지 않습니다.

## 6. 정보 상태·버전·변경 정책

### 공통 학년 코드

- 학교급별로 중학교 MIDDLE_1~3, 고등학교 HIGH_1~3을 시스템 고정 코드로 제공합니다. 관리자 UI에서는 선택/사용 여부만 처리하며 코드 추가·삭제·키 변경은 허용하지 않습니다. 학년명과 순서는 FE·BE 공통 계약에서 관리합니다.

### 상태

- 학교: 활성/비활성.
- 학년도 편성: 초안/적용/종료.
- 과목·교과서·목차: 초안/확인/적용/종료.
- 콘텐츠: 초안/검수 요청/승인/반려/게시/보관.
- 일정: 초안/검증 오류/게시 예약/게시 중/종료/취소.

각 상태는 UI 배지로 보이며 색상만으로 상태를 전달하지 않습니다.

### 변경 영향

- 게시 시점에 학교·학년도·학년/과목 편성, 교과서 판본, 목차 단원 식별자와 표시명, 세션 ID·목표 문장, 단계별 콘텐츠 버전을 일정 스냅샷으로 함께 고정합니다.
- 게시 이후 편집은 새 버전을 만듭니다. 이미 배정된 학습 기록은 기존 스냅샷을 유지하며 새 버전을 반영하려면 명시적 일정 변경/재게시를 거칩니다.
- 변경 전 영향받는 세션, 콘텐츠, 초안·게시 일정 수를 표시합니다.
- 새 버전이 준비되면 기존 일정에 자동 소급 적용하지 않고 새 일정 또는 명시적 교체 작업을 생성합니다.
- 하드 삭제는 참조 기록이 하나도 없는 초안에 한해서 허용하고, 그 외에는 비활성/종료 처리합니다.

## 7. 권한 및 감사 이력

- 시스템 관리자: 관리자 계정·역할·세부 권한, 공통 코드, 전체 학교 접근 범위 관리.
- 학교 운영자: 허용된 학교의 교육과정·교과서·목차·일정 편집.
- 콘텐츠 작성자: 허용 범위의 세션·콘텐츠 초안 작성 및 수정.
- 콘텐츠 검수자: 콘텐츠 검토·승인·반려. 자기 작성 콘텐츠의 승인 금지 여부를 정책으로 설정합니다.
- 일정 게시자: 준비 검증을 통과한 일정 게시·변경. 검수 권한과 분리할 수 있습니다.
- 조회자: 허용된 학교/학년의 준비도 및 집계 통계 조회.
- 학생(STUDENT): 본인에게 게시·배정되고 이용 기간이 유효한 학습 수행.
- 학부모(PARENT): 본인 이용 기간과 연결 관계가 유효한 자녀의 읽기 전용 현황 조회.

**권한 판정:** 역할(RBAC)과 학교/학생 범위(ABAC)를 함께 검사합니다. FE 메뉴 숨김은 사용성 처리이며 사용자 BE/관리자 BE가 매 API에서 최종 권한과 이용 상태·기간을 확인합니다. 관리자 최소 권한 원칙, 권한 없는 API의 403, 토큰 폐기, 역할·범위 변경 감사 로그를 적용합니다.

**기간 판정:** 이용 시작일 전은 ACCESS_NOT_STARTED, 종료일 다음 날부터는 ACCESS_EXPIRED, 운영 정지는 ACCESS_SUSPENDED로 분리합니다. 종료일은 Asia/Seoul 날짜 기준으로 해석합니다. 만료는 보안 차단 이벤트로 기록하고 데이터 삭제나 완료 기록 초기화와 연결하지 않습니다. 연장·정지 해제는 수행자와 사유를 기록합니다.

**공통 코드 변경:** 시스템 고정 키는 변경·삭제하지 않고 표시 라벨/정렬/사용 여부만 관리합니다. 참조 중 비활성화는 기존 이력에 코드를 보존하면서 신규 선택에서 제외합니다. 코드 변경은 영향 API와 FE/BE 계약 버전 검토 후 적용합니다.

UI에서 버튼을 숨기는 것만으로 권한을 보호하지 않고 서버/API에서도 학교 범위, 역할, 학생·보호자 관계, 이용 기간을 검사합니다. 계정·역할·권한·공통 코드·학교·학년도·과목·교과서·목차·세션·콘텐츠·일정의 변경에 수행자, 시각, 변경 전후 값, 사유를 기록합니다.

## 8. 오류·빈 상태 처리

| 상황 | 안내와 복구 동작 |
|---|---|
| 학교 미등록 | 학교 등록 버튼과 필수 입력값을 보여줌 |
| 학년도 미적용 | 학년도 생성/적용 화면으로 연결 |
| 학과 편성 없음 | 학과 편성 목록에서 해당 학교·학년도·학년·학기 편성을 만들도록 안내 |
| 교과서/목차 미확인 | 학과 편성 상세의 해당 과목 오른쪽 패널에서 판본·목차 입력/출처 확인 |
| 세션 목표 누락 | 해당 세션 편집 화면으로 이동해 목표와 콘텐츠를 확인 |
| 승인 콘텐츠 없음 | 콘텐츠 검색/작성 화면으로 이동하고 게시 차단 이유를 표시 |
| 파일 목차 가져오기 일부 실패 | 성공/실패 행을 분리해 미리보기 후 선택 적용, 원본 파일과 결과 보존 |
| 이미 사용 중인 기준정보 삭제 시도 | 삭제 차단, 영향 일정과 비활성/종료 대안을 제시 |
| 게시 이후 교과서 변경 | 게시 당시 설정을 유지하고 영향 대상·대체 버전 반영 절차 안내 |
| 네트워크/저장 실패 | 입력 내용 보존, 재시도, 중복 생성 방지 키 적용 |
| 관리자 권한 없음 | 403 안내, 권한 요청 경로 표시, 접근 차단 기록 |
| 사용자 이용 기간 만료 | /access-expired 안내, 만료일과 문의 경로 표시, API는 ACCESS_EXPIRED 반환 |
| 시작일 전/운영 정지 | ACCESS_NOT_STARTED 또는 ACCESS_SUSPENDED 안내 및 운영자 문의 제공 |
| 참조 중 공통 코드 삭제 | 삭제 차단, 사용 중 화면/데이터 표시, 비활성화 대안 제시 |

## 9. 구현 순서와 산출물

1. **접근 제어 기반:** 관리자별 역할·권한·학교 범위, 사용자 이용기간/상태, 공통 코드 스키마와 감사 로그.
2. **기초 엔티티/API:** 학교, 학년도, 학년별 과목, 교과서 판본, 단원 트리, 세션 목표와 콘텐츠 버전 정책.
3. **기준 정보 UI:** 학교 상세 → 학과 편성 목록 → 좌측 과목 선택 → 우측 출판사·교과서·목차 관리.
4. **콘텐츠 연결/검수:** 세션 목표 입력과 단계별 승인 콘텐츠 준비도.
5. **일정 준비도/편성:** 일정 전 검증, 날짜별 새 학습·공통 복습 배치, 미리보기.
6. **게시/학생 배정:** 권한·대상 확인, 게시와 변경 감사 기록.
7. **진행 현황:** 학년 집계, 단계별 완료와 개인 복습 상태.

구현 검토는 먼저 부안중학교·2026학년도·중2 수학·교과서 목차에 실린 `연립일차방정식과 그 해`를 등록해, 일정 게시까지 누락된 정보 없이 완주할 수 있는지 확인합니다. 목표 문장, 선수 개념과 문항 난이도는 담당 수학 교사의 확인 후 교육 콘텐츠 기준으로 사용합니다.

## 10. MVP 인수 조건

- 관리자 계정별로 역할 및 학교 범위를 다르게 부여할 수 있고, 권한 없는 메뉴/API 접근이 차단됩니다.
- 공통 코드를 FE/BE가 동일한 안정 키로 사용하며 참조 중 코드는 삭제할 수 없습니다.
- 사용자의 시작일·종료일·정지 상태를 설정할 수 있고 만료 후 BE 접근이 차단되며 FE가 /access-expired로 안내합니다.
- 관리자가 학교와 학년도를 등록/선택할 수 있습니다.
- 해당 학년의 개설 과목을 편성하고 적용 상태를 볼 수 있습니다.
- 과목에 출판사·교과서·판본을 연결하고, 단원 목차를 순서가 있는 트리로 입력하거나 가져올 수 있습니다.
- 단원별 세션에 목표 문장 하나를 직접 입력하고 단계별 승인 콘텐츠 준비 여부를 볼 수 있습니다. 진행 집계와 복습 연결은 세션 ID를 기준으로 합니다.
- 준비 조건을 충족하지 못하면 학생 대상 일정 게시가 막히며, 빠진 설정으로 바로 이동할 수 있습니다.
- 준비된 대상/단원에서 날짜별 새 학습과 공통 누적 복습을 편성하고 학생 미리보기를 볼 수 있습니다.
- 게시 이후 기준정보 변경이 과거 학습 기록을 덮어쓰지 않고 변경 이력을 남깁니다.
- 개인 복습 일정과 공통 게시 일정을 분리하여 학생별 결과에 따라 생성·조정할 수 있습니다.

## 11. 미결정 사항

1. 서비스 운영 학교 범위와 교육기관 코드를 어디서 가져올지.
2. 교과서가 없는 과목을 지원할 필요가 확인될 때 자체 목차와 출처 확인 절차를 설계할지.
3. 공식 학교 공지/출판사 자료를 확인하고 목차 출처를 승인할 책임자.
4. 학기/연중 과목과 두 권 이상 교과서의 일정상 표현 방식.
5. 학교 교육과정용 사전 데이터와 시스템 공통 코드의 승인·배포 책임자 및 코드 추가 권한 범위.
6. 학급·그룹 배정을 MVP에 포함할지, 학교·학년 전체를 먼저 지원할지.

7. 하루 학습 시간 권고치와 경고 임계치.
8. 학년도 도중 교과서 판본이 바뀌는 경우 적용 시점과 학생 이력 보존 방법.
9. 사용자별 복습 최대량과 공통 주간 복습의 중복 제거 규칙.
