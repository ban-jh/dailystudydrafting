# Daily Study 전체 진행 절차

프로젝트는 **기획 → 설계 → 개발 → 테스트** 순서로 진행합니다. 각 단계에서 필요한 내용만 정리하고, 합의한 결과를 관련 문서에 반영합니다.

## 1. 기획

무엇을 누구를 위해 만들고, 학습을 어떻게 운영할지 정합니다. 기획은 다음 네 가지 질문에 답하는 수준으로 핵심만 정리합니다.

### 학습 콘텐츠 생성

- **무엇을 제공할지:** 대상 학년·과목·단원, 학습 목표, 콘텐츠 형식과 하루 분량을 정합니다.
- **어떻게 마련할지:** 직접 작성, 교사·관리자 작성, 제휴 자료, AI 보조 중 공급 방식을 정하고 출처와 이용 권한을 확인합니다.
- **어떻게 품질을 보장할지:** 정확성, 난이도, 정답·해설, 연령 적합성을 누가 어떤 기준으로 검수하고 승인할지 정합니다.

### 스케줄 관리

- **누가 계획할지:** 관리자가 학생별·학급별로 계획을 배정할지, 학생이 직접 조정할 수 있는 범위를 정합니다.
- **어떻게 반복할지:** 학습 요일, 하루 분량, 시작일·종료일, 복습 간격과 계획 변경 권한을 정합니다.
- **계획을 놓쳤을 때:** 미완료 학습의 재배정, 일정 밀림, 휴일·중단 시 처리 원칙을 정합니다.

### 학생의 학습 방법

- 오늘 할 학습 확인 → 콘텐츠 학습 → 문제 풀이 또는 이해 확인 → 완료 기록의 기본 흐름을 정합니다.
- 학생이 진도·정답·해설을 확인하고, 다시 학습하거나 도움을 요청하는 방법을 정합니다.
- 완료의 기준과 미완료·오답일 때 이어서 할 일을 정합니다.

### 학부모 모니터링

- 학부모에게 보여줄 항목을 정합니다: 계획 대비 학습 여부, 완료한 학습과 진도, 학습 시간, 이해 확인 결과, 미완료·도움 필요 상태.
- 확인 주기와 알림 조건을 정하고, 학부모가 할 수 있는 후속 행동(격려, 일정 확인, 담당자 문의)을 정합니다.
- 학생의 학습 기록 중 무엇을 누구와 공유할지 정하고, 민감 정보는 필요한 만큼만 보여줍니다.

마지막으로 해결할 문제, 주요 사용자, 첫 버전의 포함·제외 범위와 성공 신호를 정리합니다. 기존 문서·구현 상태와 다른 점, 아직 확인되지 않은 가정도 표시합니다.

**결과물:** 콘텐츠 공급·검수 원칙, 스케줄 운영 원칙, 학생 학습 흐름, 학부모 모니터링 항목, 첫 버전 범위와 성공 신호, 미해결 질문

**완료 기준:** 누가 콘텐츠와 일정을 관리하는지, 학생이 어떻게 학습하는지, 학부모가 무엇을 확인하고 어떻게 돕는지 합의되어 있습니다.

## 2. 설계

기획에서 정한 범위를 실제로 만들 수 있도록 구체화합니다.

- 요구사항과 완료 기준을 정리합니다.
- 화면 흐름과 주요 상태를 설계합니다.
- 데이터, API, 권한, 보안 등 필요한 기술 구조를 정합니다.
- 콘텐츠 준비와 검수, 오류 및 예외 상황을 정리합니다.
- 구현 순서와 확인 방법을 정하고, 기존 문서와 구현에 반영합니다.

**결과물:** 요구사항, 화면 및 기술 설계, 콘텐츠 운영 방식, 구현 순서, 확인 기준

**완료 기준:** 각 작업의 목적과 범위, 완료 여부를 확인할 방법이 분명합니다.

## 3. 개발

합의된 설계와 작업 순서에 따라 기능을 구현하고, 변경 사항을 추적할 수 있게 기록합니다.

- 작업을 작은 기능 단위로 나누고, 각 작업에 완료 기준을 연결합니다.
- 개발 환경과 필요한 설정을 준비하고, 비밀 정보는 코드와 분리합니다.
- 화면, 서버 기능, 데이터 저장과 외부 연동을 설계에 맞춰 구현합니다.
- 입력값 검증, 권한 확인, 오류·빈 상태 처리를 구현합니다.
- 콘텐츠 작성·검수·게시와 학생 학습·학부모 확인 흐름을 구현 범위에 맞게 연결합니다.
- 설계 변경이나 범위 변경이 필요하면 이유와 영향을 기록하고 관련 문서를 갱신합니다.
- 구현한 기능과 남은 작업을 작업 기록에 반영합니다.

**결과물:** 실행 가능한 기능, 갱신된 코드와 문서, 실행·설정 안내, 남은 작업 및 알려진 제약

**완료 기준:** 합의된 기능이 개발 환경에서 실행되고, 관련 작업의 완료 기준과 변경 내역을 확인할 수 있습니다.

## 4. 테스트

구현된 기능이 요구사항대로 동작하는지 확인하고, 발견한 문제를 수정하거나 처리 방침을 기록합니다.

- 기획·설계에서 정한 요구사항과 완료 기준을 테스트 항목으로 확인합니다.
- 핵심 흐름을 확인합니다: 관리자 콘텐츠 준비·검수·게시, 일정 확인, 학생 학습·완료 기록, 학부모 학습 현황 확인.
- 정상 상황뿐 아니라 콘텐츠 없음, 잘못된 입력, 권한 부족, 네트워크·외부 서비스 오류도 확인합니다.
- 기록 중복, 일정 변경, 미완료 학습, 오답과 재학습 등 예외 흐름을 확인합니다.
- 화면 크기와 지원 기기에서 사용 가능한지, 개인정보가 의도한 권한 안에서만 보이는지 확인합니다.
- 발견한 문제를 재현 방법·영향·우선순위와 함께 기록하고 수정 후 다시 확인합니다.
- 출시를 막는 문제와 남은 위험을 정리해 출시 가능 여부를 결정합니다.

**결과물:** 테스트 항목과 결과, 결함 및 수정 기록, 남은 위험과 출시 판단

**완료 기준:** 합의된 핵심 흐름과 출시 기준을 확인했고, 출시 차단 문제가 해결되었거나 처리 방침에 합의했습니다.

## 진행 원칙

- 한 번에 한 단계씩 진행하고, 결정이 필요한 내용은 사용자와 먼저 합의합니다.
- 기존 문서나 구현과 충돌하면 영향을 확인해 함께 갱신합니다.
- 새 정보로 범위나 우선순위가 바뀌면 기획 결과부터 다시 맞춥니다.
- 결정은 근거와 영향을 짧게 기록하고, 미해결 항목은 다음 작업에 이어갑니다.
- 합의한 작업을 진행할 때는 해당 작업의 완료 기준에 따라 결과를 확인합니다.
